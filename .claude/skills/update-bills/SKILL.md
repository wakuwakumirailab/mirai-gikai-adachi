# 議案データ更新（bills / bill_contents / faction_stances）

福岡市議会公式サイトの議決結果ページをスクレイピングし、議案・議決結果・会派別採決・AI解説をDBに反映する。

DB接続は `db-access` スキルの規約に従う（本番Supabaseに `.env.production` の Service Role Key + curl REST でアクセス）。

## データソース

- 一覧トップ: `https://gikai.city.fukuoka.lg.jp/result/result/`
- 会期別ページ: `https://gikai.city.fukuoka.lg.jp/result/r{年}_gikai{回}/`（例: `r8_gikai3/` = 令和8年第3回）
  - 議案テーブルのほか、意見書案・決議案（`#ikensyo` アンカー）、請願（`#seigan` アンカー）も同ページにある
- 議案PDFは件名からリンクされている。PDF 1.6形式で `pdftotext`（poppler-utils）で抽出可能
- スクレイピング時は1〜2秒のインターバルを置き、PDFは1件ずつ順次ダウンロードする

## 対象範囲（重要）

- 取り込む: 通常議案（bill）・議員提出議案（member_bill）・意見書案（opinion）・決議案（resolution）・請願（petition）
- **取り込まない: 同意案・人事案件**（教育委員任命・固定資産評価員選任・人権擁護委員推薦など、議決結果が「同意」のもの）。DB全体でこれらは0件を維持する

## DBマッピング

### council_sessions
slug は `r8-3` 形式（令和8年第3回 → r8-3）。`name` は「令和8年 第3回定例会（6月）」形式。`council_url` に会期別ページURLを設定。

### bills
- 一意キー: `(council_session_id, bill_number, bill_type)`。upsert時はこの組で冪等に
- `bill_number`: 「第1号」形式
- `status` マッピング（**「不採択」を「採択」より先に判定すること**。部分一致で petition が誤って approved になるバグが過去にあった）:

| 議決結果 | status | status_note |
|---|---|---|
| 可決・採択 | `approved` | null |
| 承認 | `approved` | `承認` |
| 否決・不採択 | `rejected` | null |
| 継続審査・審議中 | `in_committee` | null |
| 未議決 | `submitted` | null |

- `status_order`・`publish_status_order` は GENERATED カラムなので**設定しない**
- 初回登録は `publish_status: draft`（意見書案・決議案は内容が短く即公開実績あり。ユーザー確認のうえ published 可）
- `source_url` に会期別ページURL、`committee_id` は未設定のまま（本会議中心運用）

### factions / faction_stances
会派別採決（○/×）を `faction_stances` に反映。○→`type: "for"`、×→`type: "against"`。

| 公式ページの略称 | factions.id |
|---|---|
| 自民 | jimin-fukuoka |
| 公明 | komei |
| 市民ク | fukuoka-shimin |
| 共産 | kyosan |
| 新風 | atarashii-kaze |
| 維新 | ishin |
| 自民新 | jimin-shin-fukuoka |

**無所属N は汎用の「無所属１〜６」レコードではなく議員個人名の faction レコードを使う**。マッピングは member/party ページの議席番号順:
無所属１→あべ ひでき / ２→新開 ゆうじ / ３→木村 てつあき / ４→森 あやこ / ５→川口 浩
（会派構成は改選等で変わるため、新会期の初回反映時に公式ページの構成と factions テーブルを突合すること）

### bill_contents（AI解説）
1議案につき `normal`（やさしい解説）と `hard`（詳しい解説）の2件。`title` は公式名称とは別のわかりやすいタイトル、`summary` は1〜2文、`content` は Markdown。

出力テンプレートは [docs/fukuoka/20260329_1000_福岡市議会データ取込設計.md](../../../docs/fukuoka/20260329_1000_福岡市議会データ取込設計.md) §5 を踏襲。

**会派別採決は Markdown の表ではなく箇条書きで書くこと**（既存コンテンツと統一）:

```text
- 賛成：自由民主党福岡市議団、公明党福岡市議団、…
- 反対：日本共産党福岡市議団
```

## 手順

1. **会期の確認・作成**: `council_sessions` に対象会期があるか確認。なければ作成
2. **GitHub/DB状態の確認**: 対象会期の bills 既存件数を確認し、二重取込を防ぐ
3. **スクレイピング**: 会期別ページから議案番号・件名・提出日・議決日・議決結果・会派別採決・PDFリンクを抽出。令和表記は西暦に変換（R8.2.17 → 2026-02-17）
4. **PDF取得とテキスト抽出**: `pdftotext` で抽出。種別ごとの品質差に注意
   - 条例改正案: 「理由」セクションが明確で要約に最適
   - 補正予算案: 冒頭条文は良好だが数値テーブルは断片化する。予算案は市公式の予算概要ページへのリンク提供が基本方針（`update-budget-overview` スキル参照）
   - 抽出困難な場合は公式タイトル・議決結果のみで生成し手動補記を促す
5. **AI解説生成**: normal / hard を生成。採決は箇条書き形式
6. **ユーザーレビュー（必須）**: 生成内容を提示し確認を取ってからDBに書き込む。チェック観点は CLAUDE.md「AI生成コンテンツのDB更新ルール」（日本語の自然さ・ソースとの整合・中国語漢字混入・答弁者フォーマット）
7. **DB反映**: bills → bill_contents → faction_stances の順に REST で upsert
8. **検証**: 件数突合（公式ページの議案数 × 会派数 = stances 件数）、web の議案一覧・詳細ページで表示確認
9. **公開**: Admin画面またはユーザー確認後に `publish_status: published` へ PATCH

## 議決結果のみの更新（会期閉会後）

会期中に draft/submitted で取り込み済みの場合は、閉会後に `status`・`status_note` の PATCH と `faction_stances` の INSERT のみ行う。r8-3 では「議案125〜152＋議員提出1号を更新、意見書案・決議案を新規作成、計31 bills × 12会派 = 372 stances」の実績あり。

## 継続審査案件

継続審査になった議案は最新の会期IDに `council_session_id` を更新する（1議案=1会期のまま運用）。

## 足立区議会版（このリポジトリ）での追加事項

足立区議会公式サイトは福岡市版と構造が異なる（ASP形式・PDF議案原文なし）ため、以下は足立区版固有の手順。福岡市版の記述（上記）とは別建てで参照すること。

### データソース

- 議案本体: `https://www.gikai-adachi.jp/g07_giketsu.asp`（GET検索、`kaigi`パラメータに会期の開始日・終了日・内部会期IDを指定）。**議案ごとのPDF原文は存在しない**ため、タイトル・提出日・議決結果のみが機械的に取得できる情報。
- **bill_contents（わかりやすい解説）の情報源は「会議録検索システム」**（`https://www.gikai-adachi.jp/voices/`）。本会議録は概要説明のみで個別議案の詳細は薄いため、**委員会会議録（`g08v_views.asp`）の「執行機関の説明」「質疑」「各会派からの意見」を主な情報源とする**。委員会は所管部ごとに分かれるため、対象議案がどの常任委員会（総務・区民・厚生・建設・文教・産業環境）で審査されたかをまず特定する。
  - 会議録の全文は `ACT=203` パラメータのURLで取得できる（`voiweb.exe?ACT=203&...&HUID=...`）。フォーム操作からこのURLパターンを特定すれば、以降は直接ナビゲーションで全文取得できる。
- **会派の賛否（faction_stances）の情報源は「審議結果一覧」PDF**（`会議の結果` → 対象会期 → `審議結果一覧`）。**委員会会議録の発言だけを情報源にしないこと**——委員会は少人数の代表者しか出席しないため、党の実際の本会議での賛否を正確に反映しない（第22号議案で実例あり: 委員会では共産党から1名のみ発言していたが、審議結果一覧PDFでは反対6票＝共産党の議席数と一致し、党として6名全員が反対と判明した）。
  - このPDFは議員41名（会期により変動）の個人別○×△が入った表で、会期ごとの正式な会派区分（是々非々の会など、頻繁に再編される会派も含む）が凡例に明記されている。
  - **PDFのテキスト抽出では議員名の並び順と○×記号の並び順が一致しないことがある**（縦書きヘッダー起因）。個人単位まで機械的に特定するにはPDFの画像レンダリング（`pdftoppm`、poppler）による目視確認が必要。人数と会派の議席数が一致するかで裏付けが取れる場合（例: 反対票数＝その会派の総人数）は、会派名簿と突き合わせて会派単位で確定してよい。僅差で分かれるケースは目視確認なしに個人名を断定しないこと。

### DBマッピングの違い

- `faction_stances.member_names`（text[]）に**採決当時の議員名をスナップショットで記録する**。会派の離合集散（是々非々の会など）や無所属議員の賛否の分裂が起こるため、`council_members.faction_id`（現在の所属）に依存せず、記録した時点の実態を保持する。
- 無所属議員の賛否が割れた場合は、同じ`faction_id`（無所属）で`type`違いの2レコードを登録できる（`UNIQUE(bill_id, faction_id)`制約は撤廃済み）。割れていない場合は1レコードにまとめてよい。
- `factions`の`display_name`は正式名称を使う（例:「公明党」ではなく「足立区議会公明党」）。現在の会派構成は`会派別名簿`ページで確認し、過去の採決分は上記PDFの凡例を優先する（両者が食い違う場合は採決当時のPDF凡例が正）。

### bill_contents（わかりやすい解説）

- 会議録に記載のない内容は含めない（推測で作成しない）。委員会での実際の質疑・答弁を根拠にする。
- タイトル・要約・本文の構成は福岡市版のテンプレートを踏襲してよいが、「会派別採決」の箇条書きセクションは`bill_contents`本文には含めない（`faction_stances`側で別途表示されるため重複させない）。

### 速報版会議録から作成した場合の `is_preliminary_source`

正式な会議録が確定する前の「速報版」会議録（`g07_shiryo1.asp`の速報版PDF等）をもとに`bill_contents`を作成した場合は、その`normal`/`hard`両方の行で`is_preliminary_source: true`を設定する（`packages/seed/main/bill-contents-data.ts`）。これがtrueの議案が1件でもある会期では、定例会議案一覧ページに「速報版会議録をもとに作成した解説が含まれる」旨の注記が自動表示される。

**正式版の会議録が公開されたら、以下を必ず行う**（現状の`is_preliminary_source: true`のまま放置しないこと）:

1. 正式版の会議録（`ACT=203`のURL等）で、速報版をもとに書いた`normal`/`hard`本文の内容（数値・質疑応答・答弁）に齟齬がないか再確認し、必要なら修正する
2. 修正が終わったら、対象行の`is_preliminary_source`を`false`に変更する
3. `source_references`も、速報版PDFへのリンクが残っていれば正式版会議録のURLに差し替える

**予算特別委員会・決算特別委員会は正式版の公開が他の常任委員会より遅れる**（「委員会会議録の閲覧」ページの委員会一覧を確認すると、常任委員会は当年分が既に選択肢にあっても、予算特別委員会・決算特別委員会は前年分までしか選択肢がないことがある）。該当会期の予算特別委員会分だけ`is_preliminary_source: true`のまま残ることは正常な状態なので、他の議案がすべて正式版に切り替わったからといって機械的に全件`false`にしないこと。切り替え前に必ず対象委員会が「委員会会議録の閲覧」の選択肢に当年分として現れているか確認する。

過去に、正式な会議録から作成したにもかかわらず`is_preliminary_source: true`のままになっていたケースがあった（令和8年第1回定例会の第5〜8号議案）。速報版と正式版のどちらを情報源にしたかは`bill-contents-data.ts`のコメント（`// 第n号議案 ...`）にも明記し、フラグと矛盾しないようにする。
