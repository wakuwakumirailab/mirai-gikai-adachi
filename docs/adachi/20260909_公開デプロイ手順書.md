## 足立区版の前提（福岡市版との違い）

| 項目 | 足立区版 | 備考 |
|------|----------|------|
| AIチャット（`features.aiChat`） | **false** | Vercel AI Gateway・Langfuse・コスト上限の設定はすべて**不要** |
| AIインタビュー（`features.aiInterview`） | **false** | interview 関連の環境変数は不要 |

## STEP 1: Supabase クラウドプロジェクト作成 〔ユーザー作業〕

### 1-1. プロジェクト作成

1. https://supabase.com に GitHub アカウントでサインイン
2. **New Project**
   - **Name**: `mirai-gikai-adachi`
   - **Database Password**: 強固なものを生成し**安全に保管**（後で使う）
   - **Region**: `Northeast Asia (Tokyo)`
3. **Create new project**（3〜5分）

### 1-2. 接続情報を控える

Supabase ダッシュボード > **Project Settings > API**（新UIでは **Settings > API Keys** / **Data API**）:

| 項目 | 場所 | 用途 |
|------|------|------|
| Project URL（`https://xxxx.supabase.co`） | Settings > API > Project URL | `NEXT_PUBLIC_SUPABASE_URL` / `SUPABASE_URL` |
| anon public key（`eyJ...`） | Settings > API > Project API keys > `anon` | `NEXT_PUBLIC_SUPABASE_ANON_KEY` |
| service_role key（`eyJ...`・**秘密**） | Settings > API > Project API keys > `service_role` | `SUPABASE_SERVICE_ROLE_KEY` |
| Database connection string | Settings > Database > Connection string > **URI**（`Session` または `Transaction` pooler） | マイグレーション適用に使う |
| Database Password | 1-1 で設定した値 | 接続文字列の `[YOUR-PASSWORD]` 部分 |

> 接続文字列は `postgresql://postgres.<project-ref>:<password>@aws-0-ap-northeast-1.pooler.supabase.com:6543/postgres` の形。

### 1-3. マイグレーション適用 〔このリポジトリの CLI 作業。接続文字列をもらえれば代行可〕

```bash
# 78本のマイグレーション（supabase/migrations/*.sql）を本番DBへ適用
npx supabase db push --db-url "postgresql://postgres.<project-ref>:<password>@aws-0-ap-northeast-1.pooler.supabase.com:6543/postgres"
```

- `supabase/config.toml` の `project_id` はローカル用（`mirai-gikai`）。`db push --db-url` は config を参照しないので変更不要。
- うまくいかない場合は Supabase ダッシュボード > **SQL Editor** で `supabase/migrations/` の `.sql` を**ファイル名昇順**に貼り付け実行でも可（78本）。

### 1-4. 初期データ投入 〔CLI 作業。接続情報をもらえれば代行可〕

`.env` の以下2つを**本番向けに一時的に差し替えて**実行（作業後ローカル値に戻す。もしくは `.env.production` を作り都度読み替え）:

```
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=eyJ...（service_role）
```

```bash
pnpm seed          # 会派・委員会・定例会・議案・bill_contents（現状は足立区ローカライズ済みの仮データ）＋管理ユーザー
```

- 予算概要（`budget:import`）・事務事業評価などは足立区の一次データがまだ無いため**この段階では実行しない**。
- 議案の実データは admin から取り込む（実データ投入フェーズ）。それまでは仮 seed で表示確認する運用。

### 1-5. 管理者ユーザー作成 〔ユーザー作業〕

Supabase ダッシュボードで:

1. **Authentication > Users > Add user** … メールアドレス＋パスワードを登録
2. **SQL Editor** で管理者ロールを付与:

```sql
UPDATE auth.users
SET raw_app_meta_data = raw_app_meta_data || '{"roles": ["admin"]}'::jsonb
WHERE email = '登録したメールアドレス';
```

> admin をまだデプロイしないなら、この手順は admin デプロイ時でも可。

## STEP 2: Vercel プロジェクト作成・デプロイ（web） 〔ユーザー作業〕

### 2-1. インポート

1. https://vercel.com に GitHub アカウントでサインイン
2. **Add New… > Project** → `wakuwakumirailab/mirai-gikai-adachi` を **Import**
3. 設定:
   - **Framework Preset**: `Next.js`（自動検出）
   - **Root Directory**: `web` を選択
   - **Production Branch**: `adachi/develop`
     - Import 画面に無ければ、初回デプロイ後に **Settings > Git > Production Branch** で `adachi/develop` に変更

### 2-2. 環境変数（web / チャット無効構成）

**Settings > Environment Variables** に登録（Production・Preview 両方に付けるのが無難）:

| 変数名 | 必須 | 値 | 取得元 |
|--------|------|-----|--------|
| `NEXT_PUBLIC_SUPABASE_URL` | ✅ | `https://xxxx.supabase.co` | STEP 1-2 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ✅ | `eyJ...`（anon） | STEP 1-2 |
| `SUPABASE_URL` | ✅ | 上と同じ URL | STEP 1-2 |
| `SUPABASE_SERVICE_ROLE_KEY` | ✅ | `eyJ...`（service_role・**秘密**） | STEP 1-2 |
| `REVALIDATE_SECRET` | ✅ | 任意のランダム文字列（例: `openssl rand -hex 32`） | 自分で生成。admin と**同じ値**にする |
| `NEXT_PUBLIC_WEB_URL` | ▲ | 初回は仮で `https://mirai-gikai-adachi.vercel.app`。独自ドメイン設定後に差し替え | デプロイ後に確定 |
| `ADMIN_URL` | ー | admin デプロイ後に設定（未設定なら `http://localhost:3001` 扱い。web 単体公開時は実害なし） | admin デプロイ後 |
| `NEXT_PUBLIC_GA_TRACKING_ID` | 任意 | `G-XXXXXXXXXX` | GA（STEP 4） |

**設定しないもの**（チャット無効のため不要。むしろ設定しない）:
`AI_GATEWAY_API_KEY` / `LANGFUSE_PUBLIC_KEY` / `LANGFUSE_SECRET_KEY` / `LANGFUSE_BASE_URL` / `CHAT_DAILY_COST_LIMIT_USD` / `ANTHROPIC_API_KEY`

> `CHAT_DAILY_COST_LIMIT_USD` は **未設定なら既定値 `0.5` が使われる**ため、あえて空のままにする（不正値を入れるとビルドが落ちる）。

### 2-3. デプロイ

**Deploy** をクリック → 発行 URL（`https://mirai-gikai-adachi.vercel.app` など）を確認。

### 2-4. デプロイ後

1. `NEXT_PUBLIC_WEB_URL` を発行 URL（または独自ドメイン）に設定 → **Redeploy**
2. 下の「デプロイ後チェックリスト」を実施

## STEP 3: admin（管理画面）デプロイ 〔実データ投入フェーズで対応〕

福岡市版手順 STEP 4-3 と同じ。同一リポジトリで2つ目の Vercel プロジェクトを作り **Root Directory = `admin`**、Production Branch = `adachi/develop`。

admin の環境変数（web と共通のものに加えて）:

| 変数名 | 必須 | 説明 |
|--------|------|------|
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` / `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` | ✅ | web と同じ |
| `NEXT_PUBLIC_WEB_URL` | ✅ | web の URL（キャッシュリセット呼び出し先） |
| `REVALIDATE_SECRET` | ✅ | web と**同じ値** |
| `ANTHROPIC_API_KEY` | ✅ | 議案 AI 解説（bill_contents）生成に使用。実データ取込時に必要 |

デプロイ後、web 側の `ADMIN_URL` に admin の URL を設定して web を Redeploy。

## STEP 4: Google Analytics（任意） 〔ユーザー作業〕

## 実データ投入フェーズの残タスク（デプロイとは別軸）

1. 無所属議員の個人名 … `web/src/features/bills/client/components/bill-detail/faction-stance-card.tsx` の `MUSHOZOKU_MEMBERS`
2. seed 会派名（`packages/seed/main/data.ts` の `factions`）と足立区議会の実会派構成の照合
3. 足立区議会の議案・議決結果・会派別採決の本取込（admin ＋ `packages/seed/fukuoka/` のETLスクリプトを参考に）
4. 予算概要・事務事業評価・記者会見・委員会議事録（各 `update-*` skill 相当の手順）
